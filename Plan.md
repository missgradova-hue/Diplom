# План автоматизации тестирования приложения «Путешествие дня»

## Перечень автоматизируемых сценариев

### 1. Покупка тура по дебетовой карте

#### Позитивные сценарии

1. Успешная покупка тура с использованием валидной карты, для которой банковский сервис возвращает `APPROVED`.
    - Заполнить все поля формы валидными данными.
    - Нажать кнопку «Продолжить».
    - Ожидаемый результат: появляется сообщение об успешной операции.

#### Негативные сценарии

2. Покупка тура с использованием карты, для которой банковский сервис возвращает `DECLINED`.
    - Заполнить форму валидными данными карты, для которой банковский сервис возвращает `DECLINED`.
    - Нажать кнопку «Продолжить».
    - Ожидаемый результат: появляется сообщение об отказе в проведении операции.

3. Отправка полностью пустой формы.
    - Ожидаемый результат: под  полями появляется сообщение о необходимости заполнения.

4. Отправка формы с пустым полем «Номер карты».
    - Ожидаемый результат: появляется сообщение о необходимости заполнения.
    - 
5. Ввод невалидного номера карты.
    - Ожидаемый результат: поле не проходит валидацию.
    - 
6. Отправка формы с пустым полем «Месяц».
    - Ожидаемый результат: появляется сообщение о необходимости заполнения.

7. Ввод месяца за пределами допустимого диапазона.
    - Ожидаемый результат: поле не проходит валидацию.

8. Отправка формы с пустым полем «Год».
    - Ожидаемый результат: появляется сообщение о необходимости заполнения.

9. Ввод истёкшего срока действия карты.
    - Ожидаемый результат: появляется сообщение об истёкшем сроке действия карты.

10. Отправка формы с пустым полем «Владелец».
    - Ожидаемый результат: появляется сообщение о необходимости заполнения.

11. Ввод невалидного значения в поле «Владелец».
    - Ожидаемый результат: поле не проходит валидацию.

12. Отправка формы с пустым полем «CVC/CVV».
    - Ожидаемый результат: появляется сообщение о необходимости заполнения.

13. Ввод невалидного CVC/CVV.
    - Ожидаемый результат: поле не проходит валидацию.


### 2. Покупка тура в кредит

Для формы покупки в кредит будут автоматизированы аналогичные сценарии:

1. Успешная покупка с использованием карты,  которой банковский сервис возвращает `APPROVED`.
2. Покупка с использованием карты, для которой банковский сервис возвращает `DECLINED`.
3. Отправка пустой формы.
4. Пустой номер карты.
5. Невалидный номер карты.
6. Пустое поле «Месяц».
7. Невалидный месяц.
8. Пустое поле «Год».
9. Истёкший срок действия карты.
10. Пустое поле «Владелец».
11. Невалидное значение поля «Владелец».
12. Пустое поле «CVC/CVV».
13. Невалидный CVC/CVV.

Также будут выполняться проверки корректности сохранения информации
об операциях оплаты и покупки в кредит в базе данных.


## Перечень используемых инструментов

### Java 11
Используется в рамках изученного курса и поддерживается тестируемым проектом.

### Gradle
Позволяет подключить необходимые библиотеки и запускать тесты.

### JUnit 5
Позволяет создавать тестовые методы, выполнять проверки и управлять
жизненным циклом тестов.

### Selenide
Фреймворк для автоматизации тестирования пользовательского интерфейса.

### Faker
Библиотека для генерации тестовых данных.

### JDBC
Используется для подключения к базе данных и проверки корректности
сохранения информации о проведённых операциях.

### MySQL и PostgreSQL
Системы управления базами данных, работу с которыми поддерживает
тестируемое приложение.

### Docker и Docker Compose
Используются для запуска необходимых сервисов и СУБД в изолированном
и воспроизводимом окружении.

### Allure
Используется для формирования наглядных отчётов о результатах выполнения
автоматизированных тестов.

### Git и GitHub
Используются для контроля версий и хранения исходного кода проекта.


## Возможные риски при автоматизации

1. Возможные проблемы при первоначальной настройке Docker и Docker Compose.
2. Ошибки подключения приложения к MySQL или PostgreSQL.
3. Нестабильная работа или недоступность банковского симулятора.
4. Изменение структуры пользовательского интерфейса.
5. Зависимость результатов тестов от данных, оставшихся в базе после
   выполнения предыдущих тестов.
6. Различия в работе приложения с MySQL и PostgreSQL.
7. Увеличение времени разработки из-за необходимости настройки
   тестового окружения и взаимодействия с базой данных.
8. Возможные ошибки самого тестируемого приложения, затрудняющие
   автоматизацию отдельных сценариев.
