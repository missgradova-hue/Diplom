# Отчёт по итогам тестирования приложения «Путешествие дня»

## Краткое описание

В рамках дипломного проекта было проведено автоматизированное тестирование веб-приложения «Путешествие дня».

Проверялись:

- покупка тура по дебетовой карте;
- покупка тура в кредит;
- валидация полей обеих форм;
- обработка карт со статусами APPROVED и DECLINED;
- корректность сохранения информации об операциях в базе данных.

Для автоматизации использовались Java, JUnit 5, Selenide, Gradle, JDBC, Awaitility и Allure.

Для запуска банковского симулятора, MySQL и PostgreSQL использовались Docker и Docker Compose.

## Результаты тестирования

Всего реализовано и выполнено 27 автоматизированных тестов.

По результатам итогового запуска с PostgreSQL:

- успешно пройдено — 23 теста;
- завершилось с ошибкой — 4 теста;
- доля успешно пройденных тестов — 85,19 %.

Неуспешные тесты выявляют некорректное поведение тестируемого приложения.

## Покрытые сценарии

Автоматизированными тестами проверены основные позитивные и негативные сценарии для двух способов приобретения тура.

### Оплата по дебетовой карте

Проверяются:

- успешная операция с картой APPROVED;
- операция с картой DECLINED;
- пустой номер карты;
- неполный номер карты;
- пустой месяц;
- некорректный месяц;
- пустой год;
- истёкший срок действия карты;
- пустое поле «Владелец»;
- некорректное значение поля «Владелец»;
- пустой CVC;
- некорректный CVC;
- сохранение результата операции в базе данных.

### Покупка в кредит

Проверяются:

- успешная операция с картой APPROVED;
- операция с картой DECLINED;
- пустой номер карты;
- неполный номер карты;
- пустой месяц;
- некорректный месяц;
- пустой год;
- истёкший срок действия карты;
- пустое поле «Владелец»;
- некорректное значение поля «Владелец»;
- пустой CVC;
- некорректный CVC;
- сохранение статусов APPROVED и DECLINED в базе данных.

## Обнаруженные дефекты

### 1. Некорректная обработка DECLINED-карты при оплате

При попытке оплаты картой со статусом DECLINED приложение отображает сообщение об успешной операции вместо сообщения об
отказе.

Банковский симулятор при этом возвращает статус DECLINED.

Дефект выявляется автоматизированным тестом `shouldNotPayWithDeclinedCard()`.

Ссылка на GitHub Issue:  
https://github.com/missgradova-hue/Diplom/issues/1

### 2. Некорректная валидация поля «Владелец»

Поле «Владелец» принимает цифровое значение `12345`. После отправки формы приложение не отображает ожидаемую ошибку
валидации и позволяет выполнить операцию.

Дефект воспроизводится как при обычной оплате, так и при покупке в кредит.

Дефект выявляется тестами:

- `shouldShowErrorWithInvalidHolder()`;
- `shouldShowErrorWithInvalidHolderInCreditForm()`.

Ссылка на GitHub Issue:  
https://github.com/missgradova-hue/Diplom/issues/2

### 3. Некорректная обработка DECLINED-карты при покупке в кредит

При покупке тура в кредит с использованием карты со статусом DECLINED приложение отображает сообщение об успешной
операции вместо сообщения об отказе.

При этом банковский симулятор и база данных фиксируют статус операции DECLINED.

Дефект выявляется автоматизированным тестом `shouldNotCreditWithDeclinedCard()`.

Ссылка на GitHub Issue:  
https://github.com/missgradova-hue/Diplom/issues/3

## Проверка взаимодействия с базами данных

Проект поддерживает проверку работы приложения с двумя СУБД:

- MySQL;
- PostgreSQL.

Для получения данных из базы используется JDBC.

Параметры подключения к базе данных передаются в тесты через системные свойства, благодаря чему один набор автотестов
может использоваться с обеими СУБД без изменения исходного кода.

Автоматизированными тестами проверяется сохранение статусов:

- APPROVED при успешной оплате;
- DECLINED при отклонённой оплате;
- APPROVED при успешной покупке в кредит;
- DECLINED при отклонённой покупке в кредит.

Для ожидания появления результата операции в базе данных используется библиотека Awaitility без применения фиксированных
задержек `Thread.sleep()`.

Работа автоматизированных тестов была проверена полным запуском набора тестов как с MySQL, так и с PostgreSQL. В обоих
случаях выполнено 27 тестов: 23 теста завершились успешно, 4 теста выявили некорректное поведение приложения.

## Результаты запуска с PostgreSQL

Итоговый запуск полного набора тестов с PostgreSQL:

- всего выполнено — 27 тестов;
- успешно — 23 теста;
- неуспешно — 4 теста;
- успешность — 85,19 %.

Команда запуска:

```powershell
.\gradlew clean test "-Ddb.url=jdbc:postgresql://localhost:5433/app" "-Ddb.user=app" "-Ddb.password=pass"
```

PostgreSQL используется на порту `5433`.

## Отчёт Allure

Для формирования отчёта о выполнении автоматизированных тестов используется Allure.

Тестовые сценарии имеют человекочитаемые названия, отображаемые в отчёте Allure.

После выполнения тестов отчёт можно открыть командой:

```powershell
.\gradlew allureServe
```

Неуспешные тесты соответствуют выявленному некорректному поведению тестируемого приложения.

## Общие рекомендации

По результатам проведённого тестирования рекомендуется:

- исправить обработку операций со статусом DECLINED, чтобы пользователю отображалось сообщение об отказе вместо
  сообщения об успешной операции;
- усилить валидацию поля «Владелец», исключив возможность ввода цифровых и других некорректных значений;
- после исправления обнаруженных дефектов выполнить повторный запуск автоматизированных тестов;
- продолжить использование автоматизированных тестов при внесении изменений в приложение для контроля основных сценариев
  оплаты и покупки в кредит.

Основные позитивные и негативные сценарии оплаты тура и покупки в кредит автоматизированы.

выполнено 23 теста, 4 теста завершились с ошибкой вследствие выявленного некорректного поведения приложения.

к MySQL, так и к PostgreSQL.

Обнаруженные дефекты зарегистрированы в GitHub Issues. Результаты выполнения автоматизированных тестов могут быть
представлены в отчёте Allure.
