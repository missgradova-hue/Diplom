# Отчёт по итогам автоматизации тестирования

## Что было запланировано

В рамках дипломного проекта планировалось автоматизировать тестирование приложения «Путешествие дня» по следующим
направлениям:

- тестирование формы оплаты тура по дебетовой карте;
- тестирование формы покупки тура в кредит;
- проверка позитивных и негативных сценариев;
- проверка валидации полей обеих форм;
- проверка обработки карт со статусами APPROVED и DECLINED;
- проверка корректности сохранения результатов операций в базе данных;
- проверка работы приложения с MySQL и PostgreSQL;
- формирование отчёта о результатах выполнения автоматизированных тестов.

Для реализации автоматизации были выбраны Java 11, JUnit 5, Selenide, Gradle, JDBC, Docker, Docker Compose и Allure.

## Что было реализовано

В ходе выполнения проекта была создана структура автоматизированных тестов с использованием паттерна Page Object.

Реализованы:

- класс `PaymentPage` для работы с формой оплаты;
- класс `CreditPage` для работы с формой покупки в кредит;
- класс `DataHelper` для хранения тестовых данных;
- класс `SQLHelper` для взаимодействия с базами данных;
- позитивные и негативные UI-тесты формы оплаты;
- позитивные и негативные UI-тесты формы покупки в кредит;
- проверки сохранения результатов операций в базе данных;
- возможность запуска тестов с MySQL и PostgreSQL;
- ожидание результатов операций в базе данных с помощью Awaitility;
- формирование отчётов Allure с человекочитаемыми названиями тестовых сценариев.

Всего реализовано 27 автоматизированных тестов.

При итоговом запуске полного набора тестов с PostgreSQL:

- 23 теста завершились успешно;
- 4 теста завершились с ошибкой;
- доля успешно пройденных тестов составила 85,19 %.

Неуспешные тесты выявляют некорректное поведение тестируемого приложения.

Обнаруженные дефекты зарегистрированы в GitHub Issues.

## Отклонения от первоначального плана

Основные запланированные сценарии были реализованы.

Для формы оплаты и формы покупки в кредит реализованы как позитивные, так и негативные сценарии, включая отдельные
проверки валидации полей.

Была реализована возможность запуска одного набора автоматизированных тестов с двумя СУБД — MySQL и PostgreSQL.
Параметры подключения передаются через системные свойства без необходимости изменения исходного кода тестов.

Первоначально в качестве одного из инструментов для подготовки тестовых данных была запланирована библиотека Faker. В
итоговой реализации основные тестовые данные были вынесены в `DataHelper` и задавались явно, поэтому необходимость
активного использования Faker отсутствовала.

Таким образом, основным отклонением от первоначального плана стало не сокращение объёма автоматизации, а изменение
способа подготовки тестовых данных.

## Возникшие сложности

В ходе автоматизации возникли следующие сложности:

- настройка Docker-окружения и запуск необходимых сервисов;
- настройка подключения приложения к MySQL и PostgreSQL;
- настройка PostgreSQL на отдельном порту `5433`;
- взаимодействие автоматизированных тестов с базами данных через JDBC;
- необходимость ожидания появления новой записи в базе данных после выполнения операции;
- настройка передачи параметров подключения к СУБД из Gradle в тесты;
- подбор устойчивых локаторов элементов пользовательского интерфейса;
- особенности валидации поля «Владелец»;
- обнаружение расхождения между статусом DECLINED, возвращаемым банковским симулятором, и сообщением, отображаемым
  пользователю;
- настройка формирования отчётов Allure.

Для ожидания результатов операций в базе данных была использована библиотека Awaitility, что позволило отказаться от
фиксированных задержек `Thread.sleep()`.

Для работы с различными СУБД класс `SQLHelper` был настроен на получение параметров подключения через системные
свойства.

Возникшие сложности были устранены в части тестовой инфраструктуры и автоматизированных тестов. Некорректное поведение
самого тестируемого приложения зарегистрировано в виде дефектов.

## Сравнение планируемых и фактических трудозатрат

Первоначальная оценка трудозатрат на выполнение автоматизации составляла 34–49 часов.

Фактические трудозатраты составили около 55 часов.

Превышение первоначальной оценки связано с дополнительным временем на:

- настройку тестового окружения;
- подключение и проверку MySQL и PostgreSQL;
- настройку взаимодействия через JDBC;
- отладку автоматизированных тестов;
- настройку устойчивых локаторов;
- исследование обнаруженных дефектов;
- настройку отчётов Allure.

Наибольшие дополнительные трудозатраты были связаны с настройкой тестового окружения и отладкой взаимодействия между
приложением, банковским симулятором и базами данных.

## Достигнутые результаты

В результате выполнения дипломного проекта была создана система автоматизированного тестирования приложения «Путешествие
дня».

Автоматизированы:

- позитивные и негативные сценарии оплаты по дебетовой карте;
- позитивные и негативные сценарии покупки в кредит;
- валидация полей обеих форм;
- обработка карт со статусами APPROVED и DECLINED;
- проверка сохранения результатов операций в базе данных.

Тестовый проект поддерживает работу с MySQL и PostgreSQL. Полный набор автоматизированных тестов был проверен с обеими
СУБД. В обоих случаях результаты совпали: из 27 тестов 23 завершились успешно, 4 теста выявили некорректное поведение
приложения.

Всего реализовано 27 автоматизированных тестов. При итоговом запуске с PostgreSQL успешно выполнено 23 теста, 4 теста
выявили некорректное поведение приложения.

Настроено формирование отчётов Allure. Тесты имеют человекочитаемые названия для удобства анализа результатов.

По результатам тестирования зарегистрированы три дефекта приложения в GitHub Issues.

Основные задачи, предусмотренные планом автоматизации, реализованы.
