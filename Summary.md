# Отчёт по итогам автоматизации тестирования

## Что было запланировано

В рамках дипломного проекта планировалось автоматизировать тестирование приложения «Путешествие дня» по следующим
направлениям:

- тестирование формы оплаты тура по дебетовой карте;
- тестирование формы покупки тура в кредит;
- проверка позитивных и негативных сценариев;
- проверка валидации полей форм;
- проверка обработки карт со статусами APPROVED и DECLINED;
- проверка корректности сохранения результатов операций в базе данных;
- формирование отчёта о результатах выполнения автоматизированных тестов.

Для реализации автоматизации были выбраны Java 11, JUnit 5, Selenide, Gradle, JDBC, Docker, Docker Compose и Allure.

## Что было реализовано

В ходе выполнения проекта была создана структура автоматизированных тестов с использованием Page Object.

Реализованы:

- класс `PaymentPage` для работы с формой оплаты;
- класс `CreditPage` для работы с формой покупки в кредит;
- класс `DataHelper` для хранения тестовых данных;
- класс `SQLHelper` для взаимодействия с базой данных;
- автоматизированные UI-тесты;
- проверки результатов операций в базе данных MySQL;
- формирование отчётов Allure.

Всего реализовано 17 автоматизированных тестов.

При итоговом запуске:

- 14 тестов завершились успешно;
- 3 теста завершились с ошибкой вследствие обнаруженных дефектов приложения;
- доля успешно пройденных тестов составила 82,35 %.

Обнаруженные дефекты были зарегистрированы в GitHub Issues.

## Отклонения от первоначального плана

Первоначально планировалось реализовать одинаковый набор позитивных и негативных сценариев как для формы оплаты, так и
для формы покупки в кредит.

В процессе выполнения проекта основной набор проверок валидации полей был реализован для формы оплаты по карте. Для
формы покупки в кредит были автоматизированы основные сценарии работы с картами APPROVED и DECLINED, а также проверки
сохранения статусов операций в базе данных.

Полный набор аналогичных негативных проверок каждого поля кредитной формы отдельно не реализовывался.

Также первоначально в качестве одного из инструментов для подготовки тестовых данных была запланирована библиотека
Faker. В итоговой реализации основные тестовые данные были вынесены в `DataHelper` и задавались явно, поэтому
необходимость активного использования Faker отсутствовала.

Тестирование приложения с обеими поддерживаемыми СУБД первоначально рассматривалось в плане работ. В итоговой реализации
основная автоматизированная проверка взаимодействия с базой данных проводилась с MySQL.

## Возникшие сложности

В ходе автоматизации возникли следующие сложности:

- настройка Docker-окружения и запуск необходимых сервисов;
- настройка подключения приложения к MySQL;
- взаимодействие автоматизированных тестов с базой данных через JDBC;
- необходимость ожидания появления новой записи в базе данных после выполнения операции;
- особенности валидации поля «Владелец»;
- обнаружение расхождения между статусом DECLINED, возвращаемым банковским симулятором, и сообщением об успешной
  операции в пользовательском интерфейсе;
- настройка формирования отчётов Allure.

Возникшие сложности были устранены в части тестовой инфраструктуры и автоматизированных тестов. Обнаруженные ошибки
самого тестируемого приложения были зарегистрированы как дефекты.

## Сравнение планируемых и фактических трудозатрат

Первоначальная оценка трудозатрат на выполнение автоматизации составляла 34–49 часов.

Фактические трудозатраты составили около 55 часов. Превышение первоначальной оценки связано с дополнительным временем на
настройку тестового окружения, подключение и проверку работы базы данных MySQL, настройку взаимодействия через JDBC,
отладку автоматизированных тестов, исследование обнаруженных дефектов и настройку формирования отчётов Allure.

Наибольшие дополнительные трудозатраты были связаны с настройкой тестового окружения и отладкой взаимодействия между
приложением, банковским симулятором и базой данных.

## Достигнутые результаты

В результате выполнения дипломного проекта была создана работающая система автоматизированного тестирования основных
сценариев приложения «Путешествие дня».

Автоматизированы основные позитивные и негативные сценарии оплаты, сценарии покупки в кредит и проверки сохранения
результатов операций в базе данных.

Настроено формирование отчётов Allure. По результатам тестирования обнаружены и зарегистрированы три дефекта приложения.

Несмотря на отклонения от первоначального плана по объёму автоматизации кредитной формы и использованию PostgreSQL,
основные задачи автоматизации были реализованы.
